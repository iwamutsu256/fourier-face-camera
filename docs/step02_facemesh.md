# Step 2: MediaPipe FaceMesh (Tasks API) による輪郭抽出

## 🎯 目的

映像フレームから顔の3Dランドマークを抽出し、フーリエ変換の入力として適した「一筆書き（連続した1次元配列）」のデータ構造を構築する。最新のPython環境に対応するため、MediaPipeの新アーキテクチャであるTasks APIを導入する。

## 🧠 学んだこと・データ構造

### 新世代 Tasks API とモデルの分離

MediaPipeの最新バージョンでは、従来の組み込みAPI (`mp.solutions`) が非推奨となり、汎用的な **Tasks API** へと移行された。推論エンジンとAIモデルファイル (`.task`) が分離されたため、プログラムの初期化時に `urllib` を用いてGoogleのストレージから動的にモデルファイルをダウンロードするアーキテクチャを採用した。

### グラフの探索と一筆書き順の抽出

FaceMeshの顔輪郭は「エッジの集合（無向グラフ）」として定義されている。これをそのまま描画するとペン先が空間を飛び回ってしまい、フーリエ変換（1つの連続した波の関数 $f(t)$ として扱う処理）が破綻してしまう。
そこで、隣接する頂点を順に辿っていく探索アルゴリズムを実装し、36個のエッジを連続する1つの配列リストへと変換した。

### OpenCVとMediaPipeの色空間・データ型のねじれ

1. **色空間**: OpenCV (BGR) と MediaPipe (RGB) は色の順序が異なるため `cv2.cvtColor` で反転させる。
2. **データラッパー**: Tasks APIではNumPy配列をそのまま渡せず、`mp.Image` オブジェクトでラップしてメタデータ（形式等）を付与してから推論エンジンに渡す必要がある。

## ⚙️ 処理の流れ

1. `.task` モデルファイルが存在するか確認し、なければダウンロードする。
2. カメラフレームをRGBに変換後、`mp.Image` に変換し推論 (`detector.detect`) を実行する。
3. 推論結果から、一筆書き順にソート済みのインデックスを用いて正規化座標を取得。
4. 画像の幅・高さを掛けてピクセル座標にマッピングし、`cv2.polylines` で描画する。

## ➡️ 次回やること

この一筆書きの点群座標リストを「複素平面上の点」と見なし、高速フーリエ変換（FFT）にかけて周波数成分に分解する。
